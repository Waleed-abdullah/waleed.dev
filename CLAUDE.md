# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Build & Development Commands

```bash
pnpm dev          # Start the Vite dev server on port 3000
pnpm build        # Production build (client, server and prerendered pages in .output/)
pnpm start        # Serve the production build (node .output/server/index.mjs); server-renders each request
pnpm lint         # Run ESLint
pnpm typecheck    # Run tsc --noEmit
```

No test framework is configured. Pre-commit hook runs `pnpm lint`; commit-msg hook enforces conventional commits via commitlint.

## Architecture

This is a **TanStack Start** portfolio/blog site (waleed.dev) built with Vite, TanStack Router (file-based routes), React 19, TypeScript, Tailwind CSS 4 and MDX for content. Nitro produces the server output; on Vercel it emits the Vercel Build Output (`.vercel/output`) automatically.

### Source Layout (`src/`)

- **`routes/`** - File-based routes. `__root.tsx` holds the document shell (`RootLayout`), the global head tags, the global CSS imports and the not-found page. `_with-navbar.tsx` is a pathless layout route that wraps home, `/blogs`, `/blogs/$slug`, `/recipes`, `/recipes/$slug` and `/playground` in the navbar/footer layout. `sitemap[.]xml.ts` and `rss[.]xml.ts` are server routes. Route files stay thin and render components from `modules/`.
- **`routeTree.gen.ts`** - Generated by the TanStack Router plugin on `dev`/`build`. It is committed (as the TanStack docs recommend) so `pnpm typecheck` works on a fresh clone. Do not edit it by hand.
- **`router.tsx`** - `getRouter()` creates the router (intent preloading, scroll restoration, `notFoundMode: 'root'`, and the dehydrate/hydrate hooks for post bodies).
- **`modules/`** - Feature modules (homepage, blogs, recipes, post, navbar-layout, root-layout, not-found-page, coming-soon-page). Each module owns its components and logic.
- **`core/`** - Shared code: UI components (`core/components/ui/`), utilities (`core/lib/cn/` for clsx+twMerge, `core/utils/post/`, `core/utils/sitemap/`), constants (routes, site URL, external links, hotkeys), hooks, icons, schemas, and types.
- **`posts/`** - MDX content files for blogs (`posts/blogs/`) and recipes (`posts/recipes/`). Each `.mdx` file exports a `metadata` object validated by Zod (`core/schemas/posts/`).
- **`mdx-components.tsx`** - MDX component overrides (headings, code blocks, images, links). It is the MDX `providerImportSource`, so it applies to every post.
- **`styles/`** - `globals.css` (Tailwind, theme tokens, shiki dark mode rules) and `fonts.css` (self-hosted IBM Plex Sans and IBM Plex Mono via Fontsource).

Build plugins live in `plugins/` and are wired up in `vite.config.mts`.

### Routing and Rendering

- Every page is server-rendered and prerendered at build time (`prerender` in `vite.config.mts`, with link crawling). `/sitemap.xml` and `/rss.xml` are prerendered too. Paths that match a file in `public/` are excluded from prerendering.
- On Vercel the prerendered HTML is served as static files. Locally, `pnpm start` server-renders each request: Start prerenders after Nitro has listed its static assets, so the node server does not serve the prerendered files.
- Route matching is case-sensitive (`caseSensitive: true`), so `/Blogs` is a 404 as it was on Next.js.
- Unknown URLs and unknown post slugs render `NotFoundPage` from the root route (without the navbar/footer) with HTTP 404. Post routes throw `notFound()` from their loader when the slug does not exist.
- Page transitions: `defaultViewTransition` in `router.tsx` wraps each navigation in a view transition. The page cross-fades from what was on screen to the new page (a small rise on the incoming page); the navbar and footer have their own `view-transition-name` and only their live state is shown, so they stay still. The rules live at the end of `globals.css` and are disabled under `prefers-reduced-motion`.
- Head tags come from route `head()` options. The root route sets the site-wide tags; post routes override title, description, keywords, category and Open Graph title/description. Absolute image URLs use `SITE_URL` from `core/constants/site/`.
- The GTM scripts are rendered directly in the document `<head>` by `modules/root-layout/Scripts`.

### Content System

- Post metadata: `title`, `date`, `summary`, and optional `keywords`, `category` (defaults to `Blog`/`Recipe` in the meta tags) and `image` (a `public/` path such as `/images/x.gif`, shown on the recipe card). `metadata` must be a self-contained literal `export const metadata = {...}` that references no imports or other bindings, because the `post-metadata` plugin extracts that statement on its own. Do not put the title or date in the MDX body: the post page renders its header (title, date, reading time) from the metadata.
- `core/utils/post/` uses `import.meta.glob` over `src/posts/{blogs,recipes}/*.mdx`. It works on the server and in the browser.
  - Metadata is imported eagerly through the `?metadata` query. The `post-metadata` plugin (`plugins/post-metadata.mts`) turns that import into a module that only contains the post's `export const metadata`, so post lists do not pull in post bodies. It also exports `readingMinutes` and `headings` (h2/h3 with their ids) computed from the post body; both use the helpers in `plugins/mdx-headings.mts`.
  - Post bodies are imported lazily, one chunk per post. `loadPostContent()` caches the import and marks the promise as fulfilled so `use()` can read it synchronously.
- List routes (`/`, `/blogs`, `/recipes`) read posts in their loaders and pass them to the module components as props. Invalid metadata throws, which fails the build during prerendering.
- Post routes load the post body in their loader. On the first page load, the router's `dehydrate`/`hydrate` hooks load the rendered post's chunk before hydration, so the server HTML hydrates without a fallback. If the chunk fails to load in the browser, only the post body shows the error fallback (`modules/post`); the rest of the page still hydrates.
- MDX is compiled by `@mdx-js/rollup`. Code blocks are highlighted at build time by `@shikijs/rehype` with the `one-light` and `slack-dark` themes; the `html.dark .shiki` rules in `globals.css` switch to the dark colors. A shiki transformer keeps the raw code on the `<pre>` for the copy button and marks the block's `<code>` so it does not get the inline code styles.
- `plugins/remark-heading-ids.mts` gives every heading an `id` (the same ids the `headings` export lists), used by the table of contents.
- `modules/post/post-page` is the reading view: back link, header from metadata, the MDX body, newer/older links, and an "On this page" table of contents from 1024px up.
- `plugins/remark-mdx-rs-list-spread.mts` keeps list rendering identical to the previous mdxjs-rs based build (a list followed by two or more blank lines renders its items with `<p>` wrappers).
- Dates are formatted by `formatPostDate` (`core/utils/date/`) with an explicit `'en-US'` locale and `timeZone: 'UTC'` so server and client output match.

### Key Patterns

- **Path alias:** `@/*` maps to `src/*` (`resolve.tsconfigPaths` in Vite; MDX files are included in `tsconfig.json` so the alias also works inside posts)
- **Links:** internal navigation uses TanStack Router `Link`; external, mailto and PDF links are plain `<a>` with `rel="noopener"` when they open in a new tab (not `noreferrer`, so the linked sites still receive the Referer)
- **UI components** built on Radix UI primitives with CVA for variants
- **Theme:** `next-themes` with CSS class strategy (`.dark`), OKLch color variables in `globals.css`
- **Fonts:** `@fontsource-variable/ibm-plex-sans` (all subsets, limited by `unicode-range`) plus the metric-adjusted `IBM Plex Sans Fallback` face in `fonts.css`; `--font-sans` is defined in `globals.css`. The latin file is preloaded from the root head. `@fontsource/ibm-plex-mono` (400, 500) backs `--font-mono`, used for section labels, dates, keyboard hints and code.
- **Images:** plain `<img>` elements; static files are served from `public/`
- **Animations:** Motion (Framer Motion) library, wrapped in `MotionConfig reducedMotion="user"`
- **Head tags and share images:** the root route's `head()` (`modules/root-layout/head`) gets the current path and sets the canonical URL, `og:url` and the page's share image. `plugins/og-images.mts` generates the 1200x630 share images (home, list pages, one per post) into `public/og/` when the dev server or a build starts; that folder is git-ignored. `ThemeColorMeta` keeps `<meta name="theme-color">` on the current theme's background.
- **Feeds:** `/sitemap.xml` and `/rss.xml` are server routes that are prerendered (listed in `pages` in `vite.config.mts`). `public/robots.txt` points crawlers at the sitemap.
- **Background:** `modules/root-layout/terrain-background` draws a dot grid whose dots swell and shrink with drifting 3D value noise, on a fixed canvas behind every page (about 20fps; one still frame under `prefers-reduced-motion` and on touch screens). Its color and strength come from `.terrain-background` in `globals.css`.

## Code Conventions

- **Imports:** `eslint-plugin-simple-import-sort` enforced - externals first, then `@/*` absolute, then relative
- **Type imports:** Inline `import type { ... }` enforced by ESLint
- **File naming:** kebab-case directories with `index.tsx` entry points (route files follow TanStack Router naming)
- **Component naming:** PascalCase
- **Formatting:** Prettier with single quotes, trailing commas (ES5), tab width 2, Tailwind class sorting plugin
- **Linting:** `typescript-eslint`, `eslint-plugin-react-hooks` (recommended), `@tanstack/eslint-plugin-router`, and the `react/*` and `jsx-a11y/*` rules that `eslint-config-next` used to enable
- **Commits:** Conventional commits required (commitlint)
